# 恒等布局读取优化（2026-09-17）

基线为 `385a4a5c5b900e53e0ec724b76ebdbe68590e3d3`。仅对已经通过访问检查、布局为恒等映射的普通 NumPy 数组，把“按活动坐标采集，再赋入结果”换为直接按掩码复制到新分配结果。返回值仍独立于输入，提取操作继续使用其选定坐标；NumPy 子类保留原有索引读取路径。

## 三轮性能确认

冻结协议包含三个不含输出 mem.store 的公开 SSA 算术程序，分别覆盖连续、Fortran 布局和反向视图。每轮在新的旧/新 Python 进程中测量，每场景九个样本、每样本五次解释调用。跟踪开关、带输出写入的对应程序、前端安排的 affine/softmax 都作为对照，不能把此处比值解释为通用 Triton GPU 或端到端加速。

三轮未开启轨迹目标的几何平均加速为 **7.611 / 7.147 / 7.198×**。每目标至少 1.10×、每轮平均至少 1.15×、所有目标和对照不退化超过 5% 的预设门槛全部通过。48 条成对记录中的完整轨迹指纹全部一致，最大观测退化为 1.754%。

| 读取为主的目标 | 三轮时间加速范围 | warm 分配峰值最小下降 |
|---|---:|---:|
| `read_1024x257_contiguous` | 9.165–10.591× | 71.28% |
| `read_16x8x16x32_fortran` | 6.323–6.485× | 81.63% |
| `read_513x255_reversed` | 5.919–6.419× | 71.21% |

峰值是预先分配输入之外、公开 interpret_program 调用期间的 tracemalloc 数据，不是 RSS。包含输出写入的控制程序、开启轨迹的程序以及冷缓存记录均完整保留，不用最有利场景代替整个解释器的性能。

## 正确性与取舍

- 本地无 Torch/Triton 环境：`609 passed, 15 deselected in 35.34s`。新增 32 项测试覆盖返回值独立、广播掩码、字节序、只读广播输入、等形状索引排列、符号零/NaN payload、非法形状和数组子类协议。
- 原有 42 项恒等布局/观察器回归继续包含在上述计数中；没有缩小掩码、别名或边界测试范围。
- 初版在 helper 中判断 whole_tensor，一项带轨迹对照退化约 5.5%，未采用。随后将判断移到 read 入口、减少通用提取路径开销，并按同一协议重测；两轮原始记录都保存。
- 同一冻结源码的 15 项真实 GPU 差分通过；新增 32 项及先前 42 项边界回归在远端 NumPy 1.26.4 上以 -W error 通过：`74 passed in 3.09s`。全部输入文件在运行前后按 SHA-256 核对一致。本地测量环境为 Python 3.12.14 / NumPy 2.3.5 / macOS arm64。
