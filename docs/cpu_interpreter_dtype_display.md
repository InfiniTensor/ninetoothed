# 快照dtype格式化：三版探索均未采用

基线16ddfd1。第一版缓存字符串内容，通过832项CPU回归，但首对进程的7个完整轨迹指纹不同而停止。新回归确认内容相等、pickle共享关系不同（3失败/1布尔通过）。保留所有原始记录，不将该版计时用于采用。

第二版每次返回新字符串、保持特殊dtype原行为，通过836项CPU和完整轨迹；三轮目标平均1.172703/1.181601/1.113334倍，但4个未跟踪控制超5%退化，最终REJECT。

第三版去掉结果缓存及encode/decode，按普通dtype的词干和位数直接构造名称。37专项、836项CPU、完整轨迹与内存门槛通过；三轮目标平均1.190449/1.180117/1.221047倍，仍有4个未跟踪控制超限，最终REJECT。代码范围检查表明_Execution类AST未变，memory/access/geometry文件字节相同；这不足以证明具体退化原因，也不能撤销实测结果。

本轮结束这一格式化方向，保留生产版本，不再修改门槛或对相同源码补跑到通过。没有为这三版启动GPU。局部跟踪目标变快不能替代整个预设矩阵的通过；不把失败版本当作生产收益。所有源码、协议、实际日志、输入/源指纹和失败记录保存以供复核。

## 复核范围

第二/三版各3对独立进程，7样本×3次，42计时条件，21完整轨迹对照；每点最多5%退化、每轮目标至少1.10倍、跟踪目标warm/cold峰值最多增加5%。第一版因轨迹不一致提前终止，只有首对数据，不能称其三轮完成。

第一版测试文件存在一个末尾空行格式问题，原文件及日志保留；后续格式化副本与其测试AST和位置信息一致。第二/三版在运行前均通过格式与项目风格检查。
