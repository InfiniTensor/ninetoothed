## 1. Weakness Analysis

### Case 1: 1D Vector Add with Tile

**场景**: `Tensor(1).tile((BLOCK_SIZE,))`，application 函数为 `x`。

**生成的 baseline mask** (baseline commit a1b0694):

```
mask = True 
  & pid < num_blocks             # 必要：PID 范围检查
  & pid >= 0                     # 永真（无符号整数）
  & arange < BLOCK_SIZE          # 永真（arange 生成 [0, BLOCK_SIZE)）
  & arange >= 0                  # 永真
  & pid*BLOCK + arange < N       # 必要：数据边界检查
  & pid*BLOCK + arange >= 0      # 永真（非负索引）
```

**低效点**: 7 个 mask 子条件中，4 个是编译期可判定永真的 (`>= 0`、arange bounds)，属于 **冗余 mask** (3.3.1 分类)。

**根因**: `Tensor.offsets()` (tensor.py:565-578) 无条件对每层追加 `index < size` 和 `index >= 0`，没有考虑：
- PID 索引 (`tl.program_id`) 是无符号整数，`pid >= 0` 永远为真
- arange 索引 (`tl.arange(0, BLOCK)`) 天然在 `[0, BLOCK)` 范围内
- 非负累积偏移 `pid*BLOCK + arange >= 0` 永远为真

### Case 2: Expand + Tile with Broadcast Dimension

**场景**: `x.expand((BLOCK_SIZE,)).tile((BLOCK_SIZE,))`，其中 x 是 size-1 的 1D tensor。

**生成的 baseline mask** 额外包含:

```
  & (pid*BLOCK + arange) * 0 < size    # 边界检查在广播维度上
  & (pid*BLOCK + arange) * 0 >= 0      # 永真
```

**低效点**: 广播维度导致 `0 * (pid*BLOCK + arange) = 0`，然后对常量 0 做边界检查，属于 **冗余 mask + 冗余 pointer arithmetic**。`0 >= 0` 和 `0 < size` (size > 0) 均为编译期可判定永真。

### Case 3: Divisible Tile 的 Source-Level 冗余 (新发现)

**场景**: `Tensor(ndim=1, shape=(1024,)).tile((128,))` — source size 和 tile size 均为编译期已知的具体整数且可整除。

**生成的 v0.0.1 mask**:

```
mask = True 
  & pid < 8                        # PID 上界：ceil(1024/128)
  & pid*128 + arange < 1024        # Source 上界：冗余！
```

**低效点**: 因为 1024 % 128 == 0，PID 上界 `pid < 8` 已经保证 `pid*128 + arange < 1024`。
- `pid_max = 7`，`arange_max = 127` → `pid_max * 128 + arange_max = 896 + 127 = 1023 < 1024`
- Source 上界完全由 PID 上界隐含，属于 **冗余 mask**

**根因**: v0.0.1 只跳过 source 层的 `>= 0`（下界），未检查 source size 是否被 tile size 整除从而安全消除上界。Helion 通过 `known_multiple()` 在 tile 配准阶段处理此问题。

### Case 4: Pointer 表达式中 Size-1 维度的冗余 Stride 项

**场景**: 当 tensor 的某个 source 维度语义大小为 1 或经过 expand/broadcast 产生零偏移时。

**生成的 v0.0.1 pointer 表达式**:

```
ptr + offset[0] * stride_0 + offset[1] * stride_1 + ...
```

即使 `offset[dim]` 恒为 0（如 broadcast 维度 `0 * index`），也仍然生成 `offset[dim] * stride[dim]` 项，依赖 `_BinOpSimplifier` 清理。但 `_BinOpSimplifier` 不能简化 `0 * x → 0`（会破坏 Triton 的 block 类型），因此冗余项残留在生成的 TRITON IR 中。

**根因**: 生成 stride 乘法时不检查维度是否为 size-1 或零偏移。Helion 通过 `_is_size_one()` 在 `SubscriptIndexing.create()` 中直接跳过此类维度。

## 2. 选择的特化类别

### 2.1 Divisible Tile Fast Path — Lower Bound (类别 2, v0.0.1)

**目标**: 当 tile 覆盖无尾块或索引天然在范围内时，跳过冗余 mask 条件。

**启用条件**:
1. **arange 层** (innermost tile level): 无条件启用。arange 索引永远在 `[0, BLOCK)` 范围内，跳过 `arange < BLOCK` 和 `arange >= 0`。
2. **PID 层** (outer tile levels): 无条件启用。`pid >= 0` 对无符号整数永远为真。
3. **Source 层** (累积偏移): 当 `_levels` 中无非 tile 一元层 (如 pad) 时启用。非负累积偏移的 `>= 0` 永远为真。

**回退条件**: 当检测到一元层 (unsqueeze、pad、负 start 切片等) 时，`has_unary_level = True`，source 层保留 `>= 0` 检查。arange 和 PID 层的跳过仍然生效。

### 2.2 Broadcast/Scalar Fast Path (类别 3, v0.0.1)

**目标**: 简化广播维度的常量表达式。

**启用条件**:
1. `0 + x → x` 和 `x + 0 → x`: 无条件启用。
2. `0 >= 0 → True` 和 `0 < expr → True`: 无条件启用。这类表达式只能由广播维度的 `0 * index` 产生，索引为常量 0 时边界检查永真。

**回退条件**: 表达式形式不匹配时保持原样。

### 2.3 Divisible Tile Fast Path — Upper Bound (类别 2, v0.0.2, Helion 启发)

**目标**: 当 source 维度 size 被 tile size 整除时，消除 source 层的 `upper_bound` mask 条件。

**参考 Helion**: `NDTileStrategy._setup_mask()` + `known_multiple()` (`tile_strategy.py:3531-3537`)

**启用条件**:
1. `has_unary_level == False`（无 unsqueeze/pad/slice 等一元层）
2. `_try_get_constant_int(source.shape[dim]) is not None`（source size 是具体整数）
3. `_try_get_constant_int(innermost.shape[target_dim]) is not None`（tile size 是具体整数）
4. `source_size % tile_size == 0`（可整除）

**回退条件**: 当 source size 或 tile size 为符号化变量（如 autotune 的 `ninetoothed.block_size()`）时，保守地保留 source 上界。这一保守策略与 Helion 的 `known_multiple()` 一致——对符号化大小返回 `False`。

**实现**: `_generate_offsets_and_mask` 中计算 `source_skip_upper` 集合，逐维传递给 `offsets()`。`offsets()` 的 `skip_upper_bound` 参数已扩展为接受 `set[int]`（per-dim）或 `bool`（全局）。

### 2.4 Size-1 Dimension Stride Skip (类别 1/3 混合, v0.0.2, Helion 启发)

**目标**: 在 pointer 表达式生成时跳过 size-1 维度的 `offset * stride` 项，避免生成冗余的 stride 乘法。

**参考 Helion**: `SubscriptIndexing.create()` + `_is_size_one()` (`indexing_strategy.py:1763-1767`)

**启用条件**:
1. `Symbol(source.shape[dim]) == 1`（编译期已知 size=1 的维度）
2. offset 节点为 `0 * (...) ` — 即 `ast.BinOp(op=Mult, left=Constant(0), right=...)`（broadcast/expand 产生的零偏移）

**实现**: `_generate_overall_offsets_and_mask` 中调用 `_is_effectively_zero_stride()` 检查。符合条件的维度直接从 `overall_offsets` 求和中跳过，不生成 `offset * stride` 项。此外，`offsets()` 中对 `Symbol(size) == 1` 的维度跳过全部 mask 边界（size-1 维度的访问永真）。

**安全性**: 与 `_BinOpSimplifier` 不同，这里是在 codegen 阶段直接跳过整个项，不涉及 AST 重写，因此不会破坏 Triton 的 block pointer 类型信息。

### 2.5 tl.max_contiguous Hint (类别 1, v0.0.2, Helion 启发)

**目标**: 在 `tl.load` 的 pointer 表达式外包装 `tl.max_contiguous(ptr, [BLOCK])` hint，帮助 Triton 后端生成向量化更好的内存访问代码。

**参考 Helion**: `_PointerLoadContiguity.derive()` + 包装模式 (`indexing_strategy.py:308,595-612`)

**启用条件**:
1. innermost 层恰好 1 个维度（1D tile）
2. `_try_get_constant_int(innermost.shape[0]) is not None` 且 `> 1`

**实现**: `_generate_pointers_and_mask` 中，在构造 `pointers` 后，若满足条件则用 `call("max_contiguous", pointers, Symbol(f"[{tile_size}]"))` 重新包装。

**局限性**: Helion 的 `_PointerLoadContiguity` 远复杂于此——包含 allowlist/blocklist 过滤、`_max_run()` 求最大连续运行长度（只对 4/8/16 字节宽度生效）、以及 NVFP4 SWIZZLE 布局检测。当前 NineToothed 仅覆盖最基础的 1D 连续 load 场景。

### 2.6 Layout-Known AOT Variant (类别 4, v0.0.3)

**目标**: 将 AOT `divisibility_spec` / `contiguity_spec` 信息反馈到 Triton IR 代码生成，使每个 AOT variant 生成专门化程度不同的 Triton 源码，而非所有 variant 共享同一份通用 IR。

**参考 Helion**: `tcgen05_static_full_tma_fast_path` (`cute_mma.py:2263`) — 当所有维度对齐时跳过边界检查; `NDTileStrategy._setup_mask()` (`tile_strategy.py:3531`)

**架构问题**: v0.0.2 及之前，`_aot()` (aot.py:60) 在枚举 variant 之前仅调用 `CodeGenerator()` 一次，所有 variant 共享同一份 Triton IR。`divisibility_spec` / `contiguity_spec` 仅在 C++ 类型标注层 (`_build_variant` 的 signature 字符串) 中使用，从未传回 mask/pointer 生成。

**解决方案**: 每个 variant 用对应的 `divisibility_hints` / `contiguity_hints` 重新调用 `CodeGenerator`，产生 variant 专用的 Triton 源码。

**代码改动**:

1. `CodeGenerator.__init__` (generation.py:29): 新增 `divisibility_hints` / `contiguity_hints` 参数
2. `_generate_offsets_and_mask` (generation.py:797-868): 接受 `divisibility_hints`; 当 AOT 提示某维度可整除时，**无条件**跳过 source 上界 mask（优先级高于编译期常数检测）
3. `_generate_overall_offsets_and_mask` (generation.py:732-785): 接受 `contiguity_hints`; 当所有 source 维度均被标记为 contiguous 时，使用线性化 pointer 表达式 `sum(offset[dim] * running_stride)` 替代外部的 `sum(offset[dim] * stride[dim])`
4. `_aot()` (aot.py:47-135): 将 `CodeGenerator` 调用移入 variant 循环; 首次调用（无 hints）获取结构性信息（`tensors`、`kernel_func`、`launch_func`、grid），之后每个 variant 用对应的 hints 重新生成 variant 专用源码

**启用条件（按 variant 类型）**:

| Variant 类型 | 触发条件 | Triton IR 变化 |
|-------------|---------|---------------|
| `divisibility_16_*` | AOT 已知 `shape[dim] % 16 == 0` + tile size 可被 16 整除 | source 层 `upper_bound` mask 消除 |
| `contiguity_1_*` | AOT 已知 `strides[dim] == 1` 对所有 dim | pointer 表达式线性化，移除 runtime stride 乘法 |
| `divisibility_* + contiguity_*` | 同时满足上述条件 | 组合优化 |
| Fallback (`int64`) | 空 spec | 保持完全通用路径（保留所有 mask + runtime stride） |

**回退保证**: 未命中 divisibility/contiguity 的 variant 通过运行时 dispatcher 的条件检查 (`shape[dim] % 16 == 0` / `strides[dim] == 1`) 选择; 不满足条件时自动回退到 int64 fallback variant。CodeGenerator 初次调用（无 hints）产生的源码等同于通用路径。

**验证数据** (1D vector add, `tile=128`):

| CodeGen 上下文 | Mask 条件数 | mask 内容 |
|---------------|:---------:|------|
| 无 hint (通用/fallback) | 2 | `pid < num_blocks & pid*128 + arange < N` |
| `divisibility_hints={(tensor,0): 16}` (AOT variant) | 1 | `pid < num_blocks` |
| `contiguity_hints={(tensor,0): True}` (AOT variant) | 2 | pointer 含线性化 offset，无 runtime stride |

### 关键代码路径 (v0.0.2 增强)

```
application DSL
  → CodeGenerator.__call__
    → visit_Name / visit_Assign
      → _generate_load / _generate_store
        → _generate_pointers_and_mask
          → tl.max_contiguous hint (NEW: §2.5)
          → _generate_overall_offsets_and_mask
            → _is_effectively_zero_stride 检查 (NEW: §2.4)
            → _generate_offsets_and_mask     ← 特化入口
              → arange level: skip_lower + skip_upper (v0.0.1)
              → PID level: skip_lower (v0.0.1)
              → source level: skip_lower + per-dim skip_upper (NEW: §2.3)
    → _BinOpSimplifier cleanup (v0.0.1: +0, 0>=0, 0<expr)
```

## Appendix A: Helion 参考架构概览

v0.0.2 的增强大量参考了 Helion 的以下核心机制：

### A.1 编译管线

```
parse → unroll → customize_ast → propagate_types → finalize_config → lower
```

其中 NineToothed 重点参考了 `lower` 阶段（`device_ir.py` 内的 mask 消除、reduction rolling、codegen）和 `tile_strategy.py`（逐维 mask 生成）。

### A.2 关键数据结构

| Helion | NineToothed 对应 |
|--------|-----------------|
| `SubscriptIndexing` (per-dim index + mask + broadcast) | `_generate_offsets_and_mask` (运行时 per-dim 构造) |
| `PerDimIndexing` (dim_index_exprs, mask_expr, broadcast_dims) | `offsets[_]` (per-dim Symbol) + `source._mask` (全局) |
| `NDTileStrategy._setup_mask()` (per-dim mask_var) | `_generate_offsets_and_mask` 三层分类 + per-dim `source_skip_upper` |
| `CompileEnvironment.known_multiple()` (compile-time divisibility) | `_try_get_constant_int()` (编译期常数提取) |
| `PointerIndexingStrategy.codegen_load()` (tl.load wrapping) | `_generate_load()` → `_generate_pointers_and_mask()` |

### A.3 Helion 独有的机制（未引入）

以下 Helion 机制未在 v0.0.2 中引入，但值得后续版本考虑：

1. **多后端索引策略分发** (`IndexingStrategy.select()`): Triton / Pallas / CuTe / Metal 四种后端，通过策略模式选择 Pointer/BlockPtr/TensorDescriptor 索引方式
2. **FX Graph 层的 mask 消除** (`remove_unnecessary_masking`): 在 IR 层检测并移除冗余 `_mask_to` 节点
3. **Pallas deferred mask** (`defer_pallas_load_masks`): major-dim load mask 推迟到 consumer 处理
4. **Reduction rolling**: 数值分析后用小步长迭代替代完全展开
5. **Lane loop 优化**: `split_lane_loop_reductions`、`hoist_lane_invariant_chunk_recurrence` (CuTe 特定)

## Appendix B: Baseline `_generate_autotune` Bug

### B.1 发现背景

在 benchmark 验证过程中，`unsqueeze_fallback` 和 `slice_fallback` 两个场景在 baseline (commit a1b0694) 上抛出 `AttributeError`，导致 kernel 生成失败。经诊断，该 bug 影响所有满足以下条件的场景：

1. `application.__annotations__` 中 tensor 的 `innermost().shape` 包含符号化 size（非具体整数）
2. arrangement 没有使用任何 meta 参数（如 `ninetoothed.block_size()`）
3. 符号对象未设置 `upper_bound`（非 meta、非 constexpr）

### B.2 崩溃路径

**文件**: `src/ninetoothed/generation.py`，`_generate_autotune()` 方法

**baseline 代码** (a1b0694, lines 398-408):

```python
max_values_of_non_meta_params = {}

for free_symbol in inequalities.free_symbols:
    symbol_str = str(free_symbol)

    if symbol_str in meta:
        continue

    symbol = self._symbols[symbol_str]            # ← ①

    max_values_of_non_meta_params[symbol_str] = symbol.upper_bound  # ← ②
```

**崩溃点 ①** (`self._symbols[symbol_str]`): 当 `sympy` 从 string 解析出的符号名不在 `self._symbols` 中时，抛出 `KeyError`。防御性写法应为 `self._symbols.get(symbol_str)`。

**崩溃点 ②** (`symbol.upper_bound`): 非 meta、非 constexpr 的 `Symbol` 对象没有 `upper_bound` 属性，直接访问抛出 `AttributeError`。`Symbol.__init__` 仅在 `lower_bound`/`upper_bound` 显式传入或符号为 meta/constexpr 时设置这两个属性（`symbol.py:71-80`）。

### B.3 触发条件分析

| 条件 | 说明 |
|------|------|
| `inequalities.free_symbols` 非空 | `math.prod(arg.innermost().shape)` 中的符号化 size 被 `sympy` 解析为自由符号 |
| `meta` 为空 | 无 `block_size()` 等 meta 参数，`symbol_str in meta` 永不为真，不会跳过 |
| Symbol 无 `upper_bound` | 默认创建的 Symbol 只有 `_node` 属性，没有 `lower_bound`/`upper_bound` |

### B.4 为什么现有 76 个测试从未触发

所有 `test_generation.py` 的测试用例都使用 `ninetoothed.block_size()` 作为 tile size（meta Symbol），或使用具体整数作为 tile size：

- **meta 路径**: `inequalities.free_symbols` 中的符号在 `meta` 集合中，被 `if symbol_str in meta: continue` 跳过，不进入崩溃路径。
- **具体整数路径**: `innermost().shape = (1024,)` 是具体整数，`sympy.simplify("1024")` 返回 `Integer(1024)`，无自由符号，`inequalities.free_symbols` 为空，循环不执行。

### B.5 修复方案

```python
# 修复后 (generation.py:406-414)
symbol = self._symbols.get(symbol_str)       # KeyError → None

if symbol is None:                            # 缺失符号，跳过
    continue

upper_bound = getattr(symbol, "upper_bound", None)  # AttributeError → None

if upper_bound is None:                       # 无 bound，跳过
    continue

max_values_of_non_meta_params[symbol_str] = upper_bound
```

**修复效果**:

- 符号有 `upper_bound` 时，行为与 baseline 完全一致
- 符号无 `upper_bound` 时，静默跳过，`max_values_of_non_meta_params` 保持为空
- 后续 `inequalities.subs({})` 不做替换，`simplify_logic` 返回原表达式
- 由于 `meta` 也为空，`block_size_configs` 生成一个空配置，`len(configs) <= 1` → `return None`（不启用 autotune）
- 语义等价于无 autotune 的通用路径，正确性无影响

| `slice_fallback` | `AttributeError` | PASS |
