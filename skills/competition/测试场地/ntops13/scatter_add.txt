           语义：                                                               
               out = self.clone()                                               
               out.scatter_add_(dim, index, src)                                
               等价于：out[index[i][j][k]...][j][k]... += src[i][j][k]...       
   （dim=0 时）                                                                 
               沿 dim 维度，把 src 的每个元素按 index 累加到 self 的对应位置。  
                                                                                
           要求：                                                               
           - 对标 torch.Tensor.scatter_add_(dim, index, src)（in-place）或      
             torch.scatter_add(self, dim, index, src)（out-of-place）           
           - 支持 dim = 0 / 1 / -1（负索引需自动规约）                          
           - self、index、src 的 ndim 必须相同；index.dtype 必须是 torch.long   
           - 沿 dim 以外的每个维度，src.shape[d] <= self.shape[d]；             
             index.shape == src.shape（torch 的硬约束）                         
           - 支持 float32 和 float16（fp32 累加器保证精度）                     
           - 必须处理 index 冲突：多个 src 位置累加到同一个 self 位置时，       
             结果必须等于串行累加（不能丢数、不能 race condition）              
           - 当 index 含越界值时返回可读错误（不要 silent wrong answer）        
           - 输出 shape 与 self 完全相同                                        
           - 输入可能是非连续的（self / src 都可能 .t() / [:,::2]）

              - 至少 3 种 shape（1D/2D/3D）× 3 种 dim × 2 dtype

              - 全 0 index（全部累加到位置 0，最大 race）                       
              - 非连续 self 与 非连续 src

       42         # with random positions (some of which will collide).
       43         numel = 1
       44         for s in src_shape:
       45             numel *= s
       46         flat = torch.arange(numel, device=device) % max(1, dim_len /
          / 2)
       47         if dup_ratio > 0:
       48             n_dup = int(numel * dup_ratio)
       49             dup_positions = torch.randint(0, dim_len, (n_dup,), devi
          ce=device)
       50             flat[:n_dup] = dup_positions
       51         index = flat.view(src_shape)
       52 
       53     return self_t, src_t, index

       56 def _check_close(a, b, dtype, msg):
       57     if dtype is torch.float16:
       58         atol, rtol = 1e-1, 1e-2
       59     else:
       60         atol, rtol = 1e-3, 1e-3
       61     if not torch.allclose(a, b, atol=atol, rtol=rtol):
       62         diff = (a - b).abs()
       63         raise AssertionError(
       64             f"{msg}: max|diff|={diff.max().item():.4e} "
       65             f"mean|diff|={diff.mean().item():.4e}"
       66         )

   - 非连续 self + src (.t(), [:,::2,:]) — PASS
   - 越界 / 负 index / 错误 dtype 必须报错 — PASS (IndexError/TypeError)

   4. atomic_add 必要性 & IR 验证

   为什么必须用 atomic: 多个 src 位置可能映射到同一个 self 位置 (用户要求 index
   重复率 ≥ 30%、全 0 index 极端 race)。若用普通 tl.store(load + val)
   会丢失写冲突 — 在 fp16 下实测 max|diff|=22 (严重错), 在 fp32 下偶发 lost
   update。必须依赖硬件 atomic RMW。

   生成代码检查 (tests/inspect_scatter_add.py):
   - 扫描 ~/.triton/cache 下 _scatter_add_kernel.ttgir
   - 找到 tt.atomic_rmw fadd, acq_rel, gpu, ... ← 确认生成了硬件原子 fadd RMW
   - 80/106 个相关 artifact 包含 atomicrmw, 0 个 fallback 到 load-add-store

   瓶颈分解 (per-component CUDA-event timing, shape=64x64x32):
   ┌─────────────────────────────────┬─────────┬──────┐
   │ 组件                            │ 时间    │ 占比 │
   ├─────────────────────────────────┼─────────┼──────┤
   │ Triton kernel launch + GPU 计算 │ 44 μs   │ 12%  │
   │ bounds 检查 (host-device sync)  │ 96 μs   │ 27%  │
   │ fp32 working buffer clone+copy  │ 27 μs   │ 8%   │
   │ Python dispatch / 其他          │ 192 μs  │ 53%  │
   │ 总计 nt                         │ ~360 μs │ 100% │
   │ torch.scatter_add               │ ~75 μs  │ —    │
   └─────────────────────────────────┴─────────┴──────┘
   结论: GPU 实际计算只占 ~12%, 真正拖慢的是 Triton JIT 的 Python dispatch +
   显式越界检查的主机同步。torch 原生实现是 C++ dispatch + 融合 bounds-check,
   所以 75 μs 里基本全是 GPU 时间。Triton+Python 路径的 dispatch 固定开销 (~200
   μs) 在小/中规模 case 里压垮 speedup。

   已知限制

   - 维度限制: 仅支持 1D–4D (5D+ 未实现 kernel 分支)
   - dtype 限制: 仅 float32/float16, 不支持 int/bool/complex/bfloat16
   - 性能: 相比 torch 固定 ~5x dispatch overhead, 大 shape 下才有望追平
   - 非连续 self: 支持, 但需要一次 fp32 clone (额外 ~27 μs)
   - 硬件: 仅 MetaX C500 (Triton 3.0 + torch 2.6+metax) 实测; 其他 GPU 未测
