# NineToothed v0.26.0 Known Failures

These failures were observed while developing the self-test RMSNorm operator.
Use them for diagnosis, but still confirm the target repository version.

## `Tensor(0)` Scalar Becomes `pointer<fp32>`

Symptom:

```text
IncompatibleTypeErrorImpl('invalid operands of type pointer<fp32> and triton.language.float32')
```

Root cause: rank-0 tensors compile to pointer arguments in generated Triton IR.
Using them directly in arithmetic, such as `+ eps`, fails type checking.

Fix: do not model arithmetic scalar parameters such as `eps`, `alpha`, or
`scale` as `Tensor(0)` in NineToothed v0.26.0. Use a Python literal or a
kernel factory that embeds the scalar as a compile-time constant. If a wrapper
accepts a parameter but only one literal is supported, reject unsupported values
with `ValueError`.

## `Symbol` Closure Capture Fails In `application`

Symptom:

```text
NameError: '<symbol_name>' is not defined
```

Root cause: the AST transformer does not capture outer-scope `Symbol` objects
as closures into `application`.

Fix: avoid referencing `Symbol` objects inside `application`. Derive values from
tile shapes such as `input.shape[1]`, or use a factory that captures concrete
Python integers.

## Triton Constexpr Tuple Negative Indexing

Symptom:

```text
Triton cannot evaluate (1, BLOCK_SIZE)[-1]
```

Root cause: generated Triton constexpr tuple evaluation does not support
negative indices for shapes such as `(1, BLOCK_SIZE)`.

Fix: use positive indexing. For row-wise reduction tiles, use `input.shape[1]`
instead of `input.shape[-1]`.
